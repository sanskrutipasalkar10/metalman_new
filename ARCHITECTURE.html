01

Data Flow

source files → generated documents

Three source files enter through the Dashboard; a single background pipeline (process_engineering_task) walks through every requested output in a fixed order, writing a progress percentage after each stage. The table below reads like the PFD tables this same pipeline produces.

Progress Stage What happens Engine
IN Source upload Feasibility Matrix (.xlsx), Master Assembly (.stp), and Technical Drawings (.pdf) are posted to /api/analyze and saved per-task under /uploads/{task_id}_*. FastAPI UploadFile
5% Part-no. resolution Master part number is read from the filename (8–9 digit regex), falling back to the Feasibility sheet's "Part No" column. regex + pandas
15% Geometry export Master STEP assembly is exported to STL and streamed to the browser as a live 3D wireframe during processing. CadQuery
20–45% Bill of Materials Each feasibility row is matched to its PDF drawing; a vision model crops the isometric view, OpenCV strips the background, and the cleaned image is centered into the BOM template cell. Ollama / GeminiOpenCVopenpyxl
60–90% Process Flow Diagram Four sheets in sequence — Sub‑Assy Index (per‑operation STEP slices rendered to PNG), Sub‑Assy Flow, Sheetmetal Flow, BOP List — each inheriting sub‑assembly references from the operation before it. CadQuery / OCPopenpyxl
92–95% Fixture Master List Fixture rows plus the fixture photos already embedded in the feasibility workbook are matched by fuzzy row search and injected. openpyxl
97% Fitment Checksheet Reuses the part crops already extracted during the BOM stage — no second AI pass. openpyxl
98% Process FMEA Assembly / Sheet‑Metal / BOP sheets filled from a dictionary‑driven template. openpyxl
99% Control Plan Re‑extracts sub‑assembly data from the PFD stage to keep both documents in lock‑step. openpyxl
99.5% Fixture PM Master Plan Day‑wise (1–31) preventive‑maintenance schedule generated from the fixture list. openpyxl
100% Output registered Every generated file is appended to the task's files[] list, polled by the browser via /api/status/{task_id} every 1.5s. tasks_db.json

Sequential stageAI = vision model in the loopEvery stage writes its own .xlsx; nothing is generated twice

After generation, three read/write paths loop back onto the same output file — Preview (Excel COM renders a true‑extent PDF, cached by file mtime), Edit in Excel (opens the live file in place via os.startfile, saves overwrite it directly), and Correct (/api/correct patches one cell in an already‑generated file without re‑running the pipeline).
02

User Journey

screen by screen

The golden path is linear — upload, select, generate, collect. Two branches (dashed) exist for touching up a result after the fact, without re‑running anything.

1
Landing / Login

Sign in

Marketing landing page → /login. Credentials post to /api/auth/token, which returns a JWT (8‑hour expiry) and a role (Admin / Engineer). The token gates client‑side routes only — it isn't yet checked by the generation endpoints themselves.

2
Dashboard — Step 1

Upload source files

Feasibility Matrix, Master Assembly STEP, and (optionally) Technical Drawing PDFs.

3
Dashboard — Step 2

Choose what to generate

Seven output documents, each toggled independently — only the requested ones run through the pipeline.

4
Processing View

Watch it run

A live 3D wireframe of the STL, a progress bar, and a seven‑stage checklist that lights up as each threshold percentage is crossed.

5
Completion

Collect the documents

One card per generated file — Preview opens the high‑fidelity modal, Get File downloads it directly.

6
Preview Modal

Look, edit, or download

A true‑fidelity PDF renders in‑page; Edit in Excel pops the real file open in desktop Excel for hands‑on changes, Download grabs the raw .xlsx.

7
Branch · Document Correction

Fix one field without a re‑run

A dedicated page: pick the document, the column, the row — patch the value and save. Useful for a typo that doesn't warrant regenerating an entire BOM.

8
Branch · Cropper

Manual capture tool

A standalone PDF‑region cropper that appends each capture to a running "welding sheet" workbook — independent of the main generation pipeline.

03

Overall Architecture

client to disk, six layers

A single FastAPI process fronts everything. There's no queue or worker fleet — process_engineering_task runs in‑process as a FastAPI background task, which is why the whole design assumes one server on one machine.
